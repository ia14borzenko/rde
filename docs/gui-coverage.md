# Покрытие GUI RDE: матрица «возможность ↔ интерфейс»

Итерация **`gui-pickers`** (GUI-02, 2026-10-29). Задача: весь пользовательский функционал RDE
гарантированно доступен **из интерфейса** и работает из него; везде, где пользователь вводит путь,
есть кнопка **«Проводник…»** с системным выбором файла/папки; найденные недочёты исправлены или
явно вынесены в ограничения.

Как читать таблицу:

| Статус | Значение |
|---|---|
| ✅ | работает из GUI (есть точка входа, есть обратная связь в журнале) |
| 🧪 | покрыто автотестом (unit/kittest; тесты в `crates/rde-ui/src/lib.rs`, `file_dialog.rs`, `rde-core/src/settings.rs`) |
| ⚠️ | работает, но было неудобно/неочевидно — **исправлено в этой итерации** (что именно — в §7) |
| ❌ | недоступно из GUI — причина указана, вынесено в «известные ограничения» (§9) |
| 👀 | требует ручной проверки на рабочем столе (в headless-сессии не проверяется) |
| 🤖 | агентское (MCP/ACP) — в GUI не дублируется осознанно, обоснование рядом |

**Метод аудита.** Инвентаризация трёх сторон: (1) публичные API и операции ядра
(`rde-core/ops`, `rde-doc`, `rde-sources`, `rde-vcs`, `rde-dag`, `rde-run`, `rde-templates`),
(2) CLI-ветки `apps/rde/src/main.rs`, (3) реестр MCP-инструментов
(`rde-mcp/src/tools.rs`). Для каждой возможности найдена GUI-точка входа: `Cmd`/`TreeAction`/
кнопки панелей/контекстные меню/диалоги/горячие клавиши. Строки «файл:строка» — на момент
итерации (line numbers сдвигаются, функция названа рядом).

## 2. Команды оболочки (лента `ribbon.rs` → `RdeApp::run_cmd`, `lib.rs:3430`)

Все команды проходят через единый диспетчер `run_cmd`; доступность — `cmd_enabled`, состояние
переключателей — `cmd_checked`. Тест полноты: каждая команда ленты есть в `Cmd::ALL`, каждая
команда `Cmd::ALL` — на ленте или в документированных панельных контролах.

## 11. Известные ограничения и следующий шаг (честно)

| Ограничение | Причина | Следующий шаг |
|---|---|---|
| Системное окно «Проводника…» не проверено автотестом вживую | в headless-сессии нет `DISPLAY`/`WAYLAND_DISPLAY`; настоящее модальное окно нельзя открыть в kittest | ручная проверка на рабочем столе (§12), проверены аргументы/коды CLI и фейковый backend |
| Полнотекстовый поиск по файлам проекта | в GUI есть фильтр по объектам; `project_search` — инструмент агента | диалог поиска по содержимому (следующая итерация) |
| Список версий документа и восстановление произвольной версии | backend `document_revisions`/`restore_document_revision` есть, GUI-диалога нет | «История документа…» с ревизиями (следующая итерация) |
| Правка формулы «в тексте документа» (каретка к вставке + `equation.edit`) | API WordCraft не умеет ставить каретку к формуле объекта; `session.sel` напрямую — хак (спайк A §5.2) | следующий шаг: навигация по `RdeInsert.para_id` + `equation.edit` |
| Редактирование `inputs`/`fragments` формулы и ручной метки нумерации (`numbering.label`, R-DOC-15) в GUI | панель P4 правит title/LaTeX/display/`mode`; входы/фрагменты сохраняются, но задаются файлом/агентом; `label` не выведена | отдельный блок «входы/фрагменты» в панели формулы |
| Пикер для относительных путей данных артефакта (`inputs/…`) | путь относителен каталога артефакта; выбор файла требует копирования в объект (меняет продуктовую логику) | «Прикрепить файл данных…» с копированием в `inputs/` |
| Откат отдельного файла из git, веб-архив (`archive_url`) | UI-сценарии не в этой итерации; `monolith` не установлен в окружении | отдельные команды/диалоги |
| Save-диалог (`Проводник…` → «Сохранить как…») | API `PickKind::Save` реализован и покрыт тестами, но фиксированный `exports/` сохранён, чтобы не менять контракт сохранения | «Экспорт .docx как…» / «Экспорт проекта как…» |
| Мультивыбор файлов в одном диалоге | backend CLI поддерживает по одному пути за окно; очередь — по одному | пакетный выбор для импорта нескольких `.docx` |
