# Fidelity-отчёт: импорт MathType-формул с нумерацией — display/inline, номера из Word, миграция (ADR-0019)

- **Итерация:** `import-numbered-formulas` (2026-10-29)
- **Проверяемое:** R-DOC-39/44 (импорт `.docx` с MathType) → явная миграция «Принять формулы как
  объекты» → display-формулы становятся block-вставками с номером справа, inline остаются inline,
  номера Word сохраняются (или назначаются по схеме проекта), пунктуация после формул не теряется.
- **Стенд:** Microsoft Word **отсутствует** (Word-часть — `unverified`); независимые оракулы —
  LibreOffice 26.2.6 (headless PDF), layout WordCraft (предпросмотр RDE) и ECMA-376.
- **Данные:** в git — только **синтетический** документ; реальный документ приёмки
  (`~/Desktop/v00.03.docx`) не коммитится, его числа ниже приведены как метрики, скриншоты — локально
  в `.cache-tmp/import-v0003/e2e/`.

## 4. Ограничения (честно)

- **Word не проверен** (на стенде отсутствует): `m:oMathPara` + табы + пунктуация в одном `w:p` и
  `m:mathPr/mathFont` в экспорте — `unverified`; LO и layout WordCraft рендерят корректно.
- Смешанные абзацы (display-формула + содержательный текст) **не нумеруются** — остаются inline с
  предупреждением (политика ADR-0019 §3.7); автономера Word без литерального кэша (`#`/eqArr)
  назначаются по схеме с предупреждением.
- Реальный документ: 64 вставки на 62 project-level объекта (повторяющиеся формулы делят объект —
  штатное переиспользование ADR-0005).
- Плейн-текстовые ссылки вида `(1)` в тексте не автодетектируются (остаются текстом); формулы в
  колонтитулах/сносках и обычных таблицах не нумеруются.
- Если display-стиль MathType в документе переименован (не содержит `display`/`equation`), формула
  классифицируется как inline — безопасная деградация без потери данных.
