## 1. Рендер SVG-формулы и метрики вёрстки (release, этот стенд)

`compile_formula` — полный конвейер кэшей формулы: OMML + векторный SVG + PNG-fallback
(WordCraft mini-doc → PDF → `pdftocairo -svg` → кроп по ink-bbox → `resvg` PNG).
`formula_metrics` — вёрстка WordCraft → `MathLayout` без растеризации/PDF.

| Формула | `compile_formula`, мс | `formula_metrics`, мс |
|---|---|---|
| `x=Vt` (простая) | **84,2** | **0,152** |
| демо σ (`\sqrt{\frac{1}{N-1}\sum…}`) | **88,4** | **0,221** |
| матрица 2×2 (`pmatrix`) | **86,4** | **0,172** |

**Гейт ТЗ «рендер одной формулы ≤50 мс» — НЕ выполнен** (84–88 мс). Причина: SVG-конвейер P0
использует **два подпроцесса poppler** на формулу (`pdftocairo` + `pdftoppm` для ink-bbox) — их
запуск и составляет ~80 мс; сама вёрстка WordCraft+OMML — десятые доли мс (`formula_metrics`
0,15–0,22 мс). Практическая цена низкая: `compile_formula` вызывается **только при изменении LaTeX**
(кэши в CAS по `act_key`), «Обновить документ» неизменённые формулы не пересобирает. Устранение —
отдельная оптимизация (ин-процессный рендер SVG без poppler CLI или bbox из вёрстки вместо
`pdftoppm`) — внесено в [`docs/perf-backlog.md`](../perf-backlog.md) как **PERF-2**.

## 2. Окно редактора (headless Chrome + CDP, loopback)

| Метрика | Холодно (первый запуск профиля) | Тепло (reload/повторное открытие) |
|---|---|---|
| Готовность страницы (MathLive определён, состояние из моста загружено) | **932–1020 мс** | **770–804 мс** |
| Габариты окна (headless) | 1280×760 (CDP `Page.captureScreenshot` ≈ 1280×673 — область без декораций) | — |
| Применение LaTeX (страница → мост): `POST /api/apply` | **2 мс** | 2 мс |
| Клик «Применить» → событие в Rust | ≤ 2 мс + ≤ 40 мс опрос моста (в продукте — каждый кадр ~16 мс) | — |
| CSP-нарушения / JS-ошибки страницы | **0 / 0** | 0 / 0 |
| Сетевые запросы вне loopback | **0** (все ассеты и API — 127.0.0.1) | 0 |

Гейт ТЗ «открытие окна ≤300 мс после инициализации webview»: **в общем случае не выполняется для
первого запуска браузера** (процесс Chrome + инициализация страницы ~0,9–1,0 с; тёплый профиль
~0,8 с). Это плата за путь «отдельное окно системного браузера» вместо встроенного webview
(встроенный на стенде невозможен — спайк §1). Отдельно: сам `rde` ничего не пересчитывает при
открытии — окно живёт в отдельном процессе, GUI RDE не блокируется.

## 4. Память/жизненный цикл (качественно + headless-проверка)

* Окно — отдельный процесс браузера с изолированным профилем; «Применить»/«Отмена»/закрытие окна →
  RDE гасит процесс (kill process group), поток моста останавливается (`Bridge::shutdown` + join),
  профиль переиспользуется (кэш ассетов). Утечек каналов/потоков в тестах нет (e2e-lifecycle тест).
* Сквозной e2e: `scripts/verify-formula-editor.sh` — страница MathLive → POST → Rust-событие
  `Applied{latex}` → процесс выходит; проверяется после каждой сборки, требующей верификации.
