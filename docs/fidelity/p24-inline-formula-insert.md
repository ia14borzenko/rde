# Fidelity/приёмка итерации `inline-formula-insert` (2026-10-30): inline-вставка формулы в каретку

Итерация `inline-formula-insert` (P8-B3, [ADR-0023](../adr/0023-inline-formula-insert.md)). Задача —
чтобы формула из панели «Формула» вставлялась **ровно в место каретки** (в середине абзаца, «перед
запятой», с разрывом прогонов), в **правильный абзац**, без «тихого» попадания в чужой абзац/конец
документа, без мусорных дублей и без бэкапа на каждую неудачную попытку.

## 1. Что было не так (воспроизведено headless на копии рабочего проекта v0004)

Рабочий проект: `rde/rde-project` (v0004, id `01M66S6J37H11PQDWWSDEVMVCS`, 58 МБ с store; документ
`01M66S74XCYYVG9Z3H99KK8VQJ`, `report.doc.rde`, 411 737 B `word/document.xml`, 315 абзацев в разметке и
315 в модели WordCraft). Целевой абзац: `w14:paraId="200C20D9"` (ordinal **246** по порядку документа,
путь WordCraft **220**), текст «Дифференциальная составляющая Rдифф … от опорной дальности , и именно…»;
каретка — после «дальности» (байтовый offset **163**).

| Проверка | До итерации (`HEAD 55388cc`) | После итерации |
|---|---|---|
| GUI отдаёт «блок» | `Path::top(220)` → `anchor_block = 220` | `w14:paraId = 200C20D9`, ordinal 246, offset 163, текст абзаца |
| Куда попадала вставка при `anchor_block = 220` | 220-й **top-level `<w:p>`** = абзац `42F1B3E3` («19 Cumming I., Bennett J. …») — чужой абзац (именно туда легли v68/v69/v71/v73) | целевой абзац `200C20D9` |
| Позиция внутри абзаца | **конец абзаца** (`append_inline_to_block` вставлял перед `</w:p>`), «перед запятой» невозможно | **между прогонами**: sdt после `w:r` «…опорной дальности» и до `w:r` « , и именно…» |
| Якорь не найден / не сопоставлен | **молчаливый** fallback `append_paragraph` — формула в конец документа, без ошибки | `Err` с подсказкой; пакет не меняется (inline без якоря — тоже `Err`) |
| Ошибка после вставки | пакет уже записан (`write_entries_atomic` до `renumber_formula_numbers`), повторные клики плодят дубликаты | перенумерация до записи, одна атомарная запись; ошибка — 0 изменений, 0 бэкапов |

## 2. Решение (кратко; детали — ADR-0023)

1. **`rde_doc::InsertAnchor`** (`w14:paraId` приоритет, `ordinal` fallback, `offset`+`text` для позиции,
   `legacy_block` — совместимость). `FormulaInsertRequest.anchor` заменил `anchor_block`.
2. **Сопоставление «путь WordCraft → `paraId`»** — по порядку абзацев: обход `word/document.xml`
   повторяет читалку WordCraft (`w:tbl`, block-level `w:sdt`, `w:customXml`/`w:ins`/`w:moveTo`, одна
   ветка `mc:AlternateContent`, без `w:txbxContent`/удалённых блоков, с синтетическими абзацами
   block-level `m:oMath`). Число абзацев разметки и модели должно совпасть, иначе `Err`.
3. **Позиционная inline-вставка** (`insert_inline_at`): реконструкция текста абзаца модели с обратной
   картой на разметку, проверка префикса по тексту, разрыв `w:r`/`w:t` с дублированием `w:rPr` и
   `xml:space="preserve"`, разрыв `w:hyperlink`; ошибка для полей/трек-правок/вложенных content-control.
4. **Display-вставка** — после top-level блока, содержащего абзац-якорь (в таблице — после таблицы с
   предупреждением).
5. **Транзакционность**: всё в памяти → перенумерация → одна запись; `InsertReport.placement/warnings`.
6. **GUI**: якорь из каретки DocView + кэш `paraId` пакета; панель показывает
   `позиция: якорь: абзац 200C20D9, позиция 163 из 418 — «…опорной дальности▸ , и именно…»`; журнал —
   `Вставка v74 (formula, omml inline) в абзац 200C20D9 после «…опорной дальности» добавлена…`.

## 3. Headless-доказательства на копии рабочего проекта (release, `/tmp/inline-fix-proj`)

Прогон `crates/rde-doc/examples/inline_probe` (временный пример; удалён после приёмки) — все проверки
прошли:

```
проект: /tmp/inline-fix-proj · абзацев XML=315 / модели=315 · целевой: path=220 paraId=200C20D9 ordinal=246 offset=163
inline: id=v74 57.8 мс · InlinePlacement { para_id: Some("200C20D9"), ordinal: Some(246), offset: Some(163),
          exact: true, context_before: "алению цели от опорной дальности", context_after: " , и именно она должна к…" }
inline-разметка: sdt в 200C20D9 · left=«Дифференциальная составляющая Rдифф пропорциональна удалению цели от опорной
          дальности» · right=« , и именно она должна компенсироваться масштабированием. …» · body_hash ok
roundtrip WordCraft: sdt на месте · абзацев=281 (реестр блоков) · вставок=74
повторная вставка: v75 — отдельный id, чужих вставок нет
неверный якорь -> Err: абзац с w14:paraId="DEADBEEF" не найден в документе (документ изменился? пересохраните и повторите)
inline без якоря -> Err: нет якоря абзаца: укажите w14:paraId каретки (режим RDE, каретка в тексте)
display: id=v76 · номер=Some("32") · после абзаца 200C20D9
ГОТОВО: все проверки inline-вставки на копии рабочего проекта пройдены
```

Что именно проверено:

- **позиция**: `left` заканчивается «…опорной дальности», `right` начинается « , и именно…» — формула
  ровно «перед запятой», как в критерии приёмки;
- **соседи не изменены**: текст всех абзацев, кроме целевого, побайтово совпал с исходным; число
  абзацев 315 → 315 (никакого нового абзаца в конце документа); чужие вставки не задеты (73 → 74);
- **реестр**: `rde:doc` содержит вставку `kind=formula`, `para_id=200C20D9` (хост-абзац), `body_hash`
  = sha256 фактического `word/document.xml`;
- **roundtrip WordCraft** (extract → open → save → `save_engine_document`): sdt и OMML на месте,
  вставка видна в реестре, число абзацев не изменилось;
- **повторная вставка** в ту же позицию — **новый** id (v75), ровно две новые вставки, дублей чужих
  абзацев нет;
- **ошибочные сценарии** (несуществующий `paraId`, inline без якоря): `Err`, пакет побайтово не
  изменён, `.bak` не создан, `.rde/doc-backups` не пополнился;
- **display-формула** с якорем по абзацу: block-sdt после блока-якоря, номер по схеме документа (32 —
  продолжение существующей нумерации проекта).

**Замеры (release, тёплый кэш, документ 411 737 B / 315 абзацев):** успешная inline-вставка
(чтение пакета + правка + перенумерация + атомарная запись zip) — **57,8 мс**; отклонённая вставка
(без записи) — **9,8 мс**. Доминирует перезапись 2,1 МБ zip-пакета, не разбор якоря.

## 6. Ограничения (честно)

1. **Word не проверен** (нет на стенде): положение inline-формулы проверено headless-разбором XML,
   рендером WordCraft и LO-оракулом; Word — `unverified`.
2. Вставка внутрь **поля Word**, **отслеживаемой правки** (`w:ins`/`w:del`) и **вложенного
   content-control** не поддерживается — понятная ошибка вместо невалидного OOXML.
3. Сопоставление «модель ↔ разметка» требует равного числа абзацев; при расхождении — ошибка
   «сохраните документ и повторите», без угадывания.
4. **Display-формула** в абзац таблицы вставляется после таблицы (предупреждение); inline внутри
   ячейки работает.
5. Несохранённые правки DocView перед вставкой автоматически сохраняются в проект (иначе reload вида
   после вставки откатил бы их) — это меняет порядок «вставка vs сохранение», но без потери правок.
6. Рабочий проект пользователя (`rde-project`) **не изменялся**: все прогоны — на `/tmp`-копии;
   ошибочные вставки v68/v69/v71/v73 в живом проекте остаются (чистка — по согласованию с
   пользователем и при закрытом RDE, см. финальный ответ).
