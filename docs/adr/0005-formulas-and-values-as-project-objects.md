## Зачем этот ADR

Фаза 1 дала **OMML-фундамент** (`rde-doc`: `insert_equation`/`add_equation`/…, OMML-гейт в
`rde-docx`), но формула пока — «содержимое документа»: у неё нет объекта, нет входов, нет
актуальности, нет связи с величинами; величины (`ConstantValue`) — только числовой литерал с
подсказкой формата. Целевая картина владельца:

> полноценная работа с LaTeX наряду с OMML; формулы и величины — объекты с
> зависимостями/актуальностью; редактор формул в интерфейсе; в выходном документе — векторная
> графика (SVG); значение/обозначение в формуле может управляться выходом артефакта; формула
> может включать фрагменты других формул.

Этот ADR фиксирует: модель данных, где что хранится, как входит в `act_key`/транзакции, как
вставляется в `.doc.rde`, как редактируется нативно, как получается вектор, как мигрировать и где
проходят границы компонентов. Продуктовый код в P0 не менялся.

## Решение (кратко)

1. **Формула — вычисляемый служебный объект документа** (не новый верхний тип, R-TREE-01,
   R-DOC-20): `objects/documents/<doc-id>/formulas/<fid>/formula.toml`, источник истины — LaTeX;
   владелец — документ; участвует в графе зависимостей и каскаде; удаляется/переносится вместе с
   документом (каскад бесплатно — `delete_object` переносит весь каталог, проверено C10).
2. **Обозначение величины — расширение `ConstantValue`** (R-ART-09), не новый тип: `symbol`,
   `subscript`, `unit`, `display`, `style` + необязательный `source` = URI выхода артефакта
   (значение-литерал **или** ссылка; `value` остаётся кэшем последнего разрешённого значения).
3. **Формула хранит свои размеченные данные сама**: `latex` (истина), `display`, `numbering`,
   `inputs[]`, `fragments[]`; документ получает только вставку (`RdeInsert kind="formula"` со
   ссылкой `rde://document/<doc>/formula/<fid>@<act_key>` и кэшем).
4. **Формула — вычисляемый узел графа**: `act_key` из существующих примитивов
   (`rde_hash::act_key` с `kind="formula"`): источник LaTeX + hashed-входы + фрагменты +
   версия рендерера. Каскад: вход → формула → документ. Откат/GC — через store (CAS + корни).
5. **Редактор — нативный WordCraft** (`equation_tab`) в панели RDE поверх `EmbeddedEditor.app`;
   webview/JS не используются (спайк A: вкладка рисуется в egui-панели без правок vendor).
6. **Вектор — SVG-кэш формулы**; в docx — `asvg:svgBlip` + PNG-fallback (MS-ODRAWXML;
   LO 26.2 проверен, Word 2016+ — по спецификации, Word на стенде нет); PDF-гейт «нет растровых
   формул» по `pdfimages`/`pdffonts`. WordCraft-writer теряет `svgBlip` при пересохранении →
   RDE переприменяет SVG-вставку после сохранения движком (RDE — владелец финальной записи).
7. **Компоненты**: модель/валидация/граф — `rde-core`; хеши — `rde-hash`; активация/статусы/
   каскад — `rde-dag` (без IO документов); компиляция/кэш/вставка/обновление — `rde-doc`;
   гейты docx/PDF — `rde-docx`; панель/действия — `rde-ui`. Новых крейтов нет; `vendor/wordcraft`
   в P1–P4 не меняется (изменения — только отдельным ADR-0001 §4, если понадобятся в P5).

## 1. Модель величины: расширение `ConstantValue` (P1)

### 1.1. Целевая схема

`rde/artifact@1`, `type = "constants"`, `[values.<key>]` (сегодня:
[`ConstantValue`](../../crates/rde-core/src/manifest.rs#L156-L167)):

```toml
[values.R_n]
# Обозначение (R-DOC-23, ГОСТ 8.417-2024): курсив/подстрочные, unit — прямое начертание
symbol = "R"                 # новое: базовая буква обозначения
subscript = "н"              # новое: подстрочный индекс (пусто — нет)
unit = "Ом"                  # было: единица
display = "R_н"              # было: как показывать текстом (совместимость v1)
style = "italic-subscript"   # было: подсказка rich-форматирования
format = "auto"              # новое: auto|raw|int|dec:N|sci:N|percent:N (rde_doc::format_value)

value = 12.4                 # было/остаётся: литерал ИЛИ кэш последнего разрешённого значения
# — ИЛИ источник значения (владелец: «значение может быть литералом ИЛИ ссылкой на выход артефакта»):
source = "rde://artifact/01M5…@dd7e…/out/stats.json#/stats/x1/mean"   # новое: URI
```

Правила:

* Ровно один **источник истины**: при непустом `source` значение разрешается из артефакта,
  `value` — кэш (обновляется RDE, как `out_hash` у compute-артефакта, см.
  [`record_artifact_out_hash`](../../crates/rde-core/src/ops.rs#L486-L518)); при пустом `source` —
  литерал, как сейчас.
* `symbol`/`subscript` — обозначение; `display` — совместимое текстовое представление (если пусто,
  строится из `symbol`+`subscript`), `style` — rich-подсказка.
* **Валидация** (`rde-core`, при загрузке — `issues`, не фатально): `source` — синтаксически
  корректный URI `rde://artifact/<id>@<out_hash>/<selector>` (или `rde://constants/<id>/<key>` для
  переиспользования величины); цель существует; `symbol` без пробелов; `subscript` без пробелов;
  единица непуста для размерных величин (эвристика R-DOC-24, предупреждение); `format` — из
  известного набора.
* **Совместимость**: новые поля — `Option`/`default`, в TOML пишутся только непустые
  (как `out_hash` с `skip_serializing_if`); JSON Schema не запрещает доп. поля
  ([`manifest.rs:347-395`](../../crates/rde-core/src/manifest.rs#L347-L395)) — старый RDE читает
  такие константы, игнорируя `source`, и видит `value` (спайк C3: `issues=0`, `display` читается).
  `value` остаётся **обязательным** — это сохраняет старую схему и совместимость (вопрос §12-4 —
  альтернатива value-less с `@2`).

### 1.2. Разрешение значения и форматирование

Целевые функции (P1):

* `rde-dag` (новый резолвер, переиспользует `resolve_insert_text`,
  [`rde-dag/src/lib.rs:1546-1578`](../../crates/rde-dag/src/lib.rs#L1546-L1578)):
  `resolve_constant(project, store, constants_id, key) -> ResolvedValue { text, unit, symbol, subscript, display, style, render_style, digest }`.
  `digest = sha256(canonical_json(разрешённое значение + формат))`; при `source` с `@out_hash`
  digest учитывает зафиксированный `out_hash` (для актуальности — сравнение с текущим).
* Текст для документа (R-DOC-11/23): значение по `format` + `\u{00A0}` (неразрывный пробел) +
  единица прямым начертанием (ГОСТ 8.417-2024, §9.7); обозначение — `symbol` курсивом +
  `subscript` подстрочным (`style`), что уже поддержано `RdeInsert.run_style`
  (`italic`/`italic-subscript`, [`rde-doc/src/lib.rs:96-102`](../../crates/rde-doc/src/lib.rs#L96-L102)).
* **Централизованная замена обозначения** (R-DOC-23): правка `symbol`/`subscript`/`unit` в объекте
  констант делает все вставки `rde://constants/<id>/<key>` устаревшими (сравнение digest) и
  обновляется штатной транзакцией документа (`update_document_transactional`,
  [`rde-doc/src/lib.rs:2618-2661`](../../crates/rde-doc/src/lib.rs#L2618-L2661)); «где вставлено» —
  скан `rde:doc.inserts` по префиксу target (обратные ссылки).
* Rich-вставка в текст/подписи/формулы: `RdeInsert kind="value"`, `value_kind="number"`,
  `run_style` из обозначения; в формулу — через вход-обозначение (см. §2.3).

### 1.3. Вхождение в `act_key`

Сегодня константы попадают в `in_hash` артефактов как
`sha256(canonical_json(ConstantValue))` по **типизированным** полям
([`rde-dag/src/lib.rs:334-361`](../../crates/rde-dag/src/lib.rs#L334-L361)) — разрешённое значение
из `source` в хеш не входит, это дефект для новой модели.

Решение: `rde-hash` получает `constant_hash(constants_id, key, resolved: &ResolvedValue)`:

```
constant_hash = H("rde:const:1" |
                  constants_id | key |
                  symbol | subscript | unit | display | style | format |
                  resolved_value_jcs | source_digest? )
```

* Для **литеральных** констант (новые поля пусты) хеш **должен совпасть** с текущим поведением,
  иначе все артефакты разом станут stale; добьёмся этого, сериализуя только непустые новые поля и
  сохранив `value` как канонический литерал (golden-тест «старый манифест → тот же хеш»).
* Для констант с `source` хеш включает `source_digest` (текущий `out_hash`+selector или закреплённый
  `@out_hash`) → пересчёт артефакта меняет `in_hash` зависимых артефактов (каскад §7.3 п.2).
* Изменение обозначения (`symbol`/`subscript`/`unit`/`style`) меняет `in_hash` — это осознанно:
  выход артефакта, использующего константу как вход, зависит от текста/оформления (R-DOC-23:
  централизованная замена); при желании «стиль не влияет» — `ref`-группа (решение: hashed, т.к.
  значение/единицы входят в результат).

## 2. Модель формулы: объект документа (P2)

### 2.1. Хранение

```
objects/documents/<doc-id>/
  document.toml
  report.doc.rde
  formulas/
    <fid>/                       # ULID, стабильный id объекта (как у остальных объектов)
      formula.toml               # LaTeX-источник + разметка (diffable)
      readme.md                  # опционально, как у артефактов
      .gitignore                 # кэши/временное не коммитятся
```

* Кэши (OMML/SVG/PNG) — **не файлы в git**, а блобы CAS store; `formula.toml` хранит только хеши
  (`omml_hash`/`svg_hash`) и `computed_at` — как `out_hash` у артефактов (модель R-VCS-02/§7.3
  п.10: git диффит происхождение без бинарных выходов).
* Кэш-дерево в store: корень `formula/<doc-id>/<fid>` → entries `formula.omml`, `formula.svg`
  (опц. `formula.png`) — Merkle, как у артефактов; транзакция `kind="formula-update"` с payload
  состояния (по аналогии с `ArtifactState`, [`rde-dag/src/lib.rs:70-96`](../../crates/rde-dag/src/lib.rs#L70-L96)).
  Это даёт откат/GC/pins формульных кэшей теми же механизмами store.
* document-scope: `delete_object` переносит каталог документа целиком (C10); перенос документа
  между проектами — вместе с формулами; `rename_object` не трогает каталог.
* Для нового `FormulaManifest` — `schema = "rde/formula@1"`, файл `formula.toml`, id = имя
  каталога (ULID), регистрация в дереве как **служебный объект-ребёнок документа** (скрыт по
  умолчанию, режим «показать служебные», R-TREE-01/02; вопрос §12-3).

### 2.2. Поля `formula.toml`

```toml
schema = "rde/formula@1"
id = "01JB…"                     # ULID; должен совпадать с именем каталога (как у объектов)
document = "01M5…"               # id документа-владельца (проверяется при загрузке)
title = "Закон Ома"
latex = "\\sigma=\\frac{F}{A}"   # ИСТОЧНИК ИСТИНЫ; LaTeX (в т.ч. подстановки §2.3)
display = true                   # true — отдельная строка (display), false — inline

[numbering]
mode = "auto"                    # none | auto | manual
number = 1                       # manual — заданный номер; auto — кэш последнего номера (R-DOC-15)

[[inputs]]                       # именованные входы; подставляются в latex по alias
alias = "F"
mode = "hashed"                  # hashed — влияет на act_key/каскад; ref — только provenance
source = "rde://artifact/01M5…@dd7e…/out/force.json#/f"   # или rde://constants/<id>/<key>
as = "value"                     # symbol | value | raw (как подставлять: обозначение/число/текст)
format = "auto"                  # для value
unit = ""                        # переопределение единицы, пусто — из источника

[[fragments]]                    # фрагменты других формул (LaTeX-кода)
alias = "ohm"
source = "rde://document/01M6…/formula/01JB…@a7a3…"       # URI формулы + закреплённый act_key

[state]                          # кэш/зеркало ledger (пишет RDE; не источник истины)
act_key = "…"                    # hex; сравнение с вычисленным = актуальность
resolved_latex_hash = "…"        # sha256 эффективного LaTeX после подстановок
omml_hash = "…"                  # sha256 OMML-фрагмента (blob CAS)
svg_hash = "…"                   # sha256 SVG (blob CAS)
png_hash = "…"                   # sha256 PNG-fallback (blob CAS)
computed_at = 0                  # unix
```

Проверки при загрузке (`rde-core`):

* `id` — ULID, совпадает с каталогом; поле `document` должно совпадать с id документа-каталога,
  в котором лежит `formulas/` (проверяется при загрузке); дубли id запрещены (как `seen_ids` в
  загрузчике, [`project.rs:441-451`](../../crates/rde-core/src/project.rs#L441-L451));
* `latex` непуст; `display` — bool; `numbering.mode ∈ {none,auto,manual}`, при `manual` номер ≥ 1;
* `inputs[].source` — URI `rde://constants/...` или `rde://artifact/...` (формула **не может**
  зависеть от формулы через `inputs` — только через `fragments`); `fragments[].source` —
  `rde://document/<doc>/formula/<fid>[@act_key]`; алиасы уникальны и встречаются в `latex`
  как `\rdeinput{<alias>}` (или не встречаются → предупреждение «вход не используется»);
* цикл по `fragments` (включая меж-документные) — ошибка проекта с цепочкой (§7.3 п.3; прототип
  DFS-детекта отработал в спайке C9);
* `state.*` — кэш, расхождение с вычисленным актуально не ломает загрузку (статус «устарел»).

### 2.3. Подстановки (значения и фрагменты)

* В `latex` допустимы команды-плейсхолдеры:
  `\rdeinput{<alias>}` — подставляется разрешённый вход: `as="value"` → число по `format`
  (для математики — без единицы; единица — отдельным плейсхолдером `\rdeunit{<alias>}` или в
  тексте «где»), `as="symbol"` → обозначение величины в LaTeX-виде
  (`R_{\text{н}}` из `symbol`/`subscript`), `as="raw"` → текст как есть;
  `\rdefragment{<alias>}` — подставляется **эффективный LaTeX** фрагмента (после его собственных
  подстановок), в скобках; фрагмент обязан быть display=false или обёрнут `\left(...\right)`.
* Эффективный LaTeX (кэш `resolved_latex_hash`) = `latex` с подстановками; компиляция OMML идёт
  из эффективного LaTeX через WordCraft `parse_latex` (спайк A: LaTeX↔linear↔OMML без потерь,
  A7–A9). Неразрешённый плейсхолдер — ошибка компиляции (статус `NotComputable`, причина в UI),
  не «тихая» подстановка.
* Ref-входы (`mode="ref"`) в `act_key` не входят (§7.3 п.1: связаны, не пересчитываются), но
  показываются в provenance/UI.

### 2.4. Компиляция кэшей (P2)

`rde-doc` (владелец документа/движка; новых крейтов нет — см. §8):

1. **OMML**: LaTeX → `wordcraft_doc::math_latex::parse_latex` → мини-`Document` с одним
   `InlineObject::Equation` → `wordcraft_engine::io::save_bytes("f.docx")` → извлечь
   `m:oMath`/`m:oMathPara` из `word/document.xml` (спайк A16: счётчики и структура корректны,
   `m:f`/`m:num`/`m:den` на месте) → blob в CAS. Альтернатива «вставить в реальный документ и
   вырезать» отклонена: компиляция не должна зависеть от состояния документа.
2. **SVG**: тот же мини-документ → `io::save_bytes_opts("f.pdf")` (векторный krilla, B1) →
   `pdftocairo -svg` (B2: 0 `<image>`, глифы путями) → кроп bbox (`pdftotext -bbox` + `viewBox`,
   B2b) → blob CAS. Зависимость — poppler CLI (уже принятое отклонение §15-2, не новая лицензия:
   внешний GPL-инструмент, не линкуется).
3. **PNG fallback**: resvg 0.45 (`rde_doc::rasterize_svg`,
   [`rde-doc/src/lib.rs:1857-1873`](../../crates/rde-doc/src/lib.rs#L1857-L1873)) → blob CAS (B4:
   830 Б для σ=F/A).
4. Запись: один store-tx `kind="formula-update"` с корнем `formula/<doc>/<fid>` и состоянием
   (act_key, компоненты, хеши, computed_at); дублировать `[state]` в `formula.toml` для
   человекочитаемости/git-диффа (прецедент `out_hash`).
5. **Идемпотентность**: одинаковый вход → одинаковые кэши (WordCraft/poppler версии входят в
   `env_hash`; при апгрейде движка кэши инвалидируются — причина «изменилось окружение»).
   Производительность компиляции не измерялась (P2 — замер и бюджет; спайки собрали только
   размеры: OMML 6,6 КБ docx, PDF 4,9 КБ, SVG 2,8 КБ, PNG 0,8 КБ).

## 3. Вставка формулы в документ (P3)

### 3.1. Модель вставки (`rde:doc`)

`RdeDoc.schema_version` повышается `1 → 2`; `RdeInsert` расширяется (поля с `serde(default)` —
старые пакеты читаются, новые поля необязательны). Псевдо-XML записи в `rde:doc`:

```
<rde:insert id="f3" kind="formula"
            target="rde://document/01M5…/formula/01JB…@a7a309ac…"
            value_kind="formula" render_mode="omml"
            cached="σ=F/A" hash="a7a309ac…"
            para_id="1234ABCD" block="16" number="1"/>
```

* `kind="formula"` — новый вид вставки R-DOC-11 (формальные правки ТЗ §9);
* `render_mode` — новое поле, настройка вставки: `omml` (по умолчанию: редактируемая формула,
  R-DOC-22 п.1) или `svg` (векторная картинка + PNG-fallback; R-DOC-22 п.2 «отрендеренное
  изображение»);
* `hash` = `act_key` формулы на момент вставки (устаревание) + сравнение кэша;
* `cached` = эффективный linear/LaTeX для diff-предпросмотра и «где вставлено»;
  `number` — отображаемый номер (auto — кэш; manual — из объекта).

### 3.2. Тело документа: sdt-обёртка и якорь

Формула вставляется как content-control (`w:sdt`, механизм of record §8.5) с
`w:tag="rde:formula:<insert-id>"`, внутри:

* **omml**: таблица 1×2 (§9.4, уже реализована `numbered_table`,
  [`equation.rs:277-305`](../../crates/rde-doc/src/equation.rs#L277-L305)): левая ячейка —
  `m:oMathPara`-фрагмент из кэша, правая — текст `(n)`; без номера — центрированный абзац с
  `m:oMathPara`; inline (`display=false`) — `m:oMath` в конце абзаца-анкора;
* **svg**: тот же sdt, но `w:drawing` с `asvg:svgBlip` + PNG-fallback (§6) внутри левой
  ячейки/абзаца; номер — текст.

Анкор: `para_id` (`w14:paraId`, R-DOC-04) + `block`-путь. `rde-doc` уже умеет инжектить
`paraId` (`inject_para_ids`) и хранить его в `rde:doc`; переприменение XML после сохранения
движком — рабочий механизм (так же делаются sdt-вставки значений/рисунков:
[`add_insert`](../../crates/rde-doc/src/lib.rs#L1756-L1798)). Если WordCraft-roundtrip сохраняет
sdt вокруг math (проверить в P3) — rewrite по тегу; если нет — rewrite по `paraId` (RDE владеет
финальной записью `write_package` после `save_engine_document`). Оба пути не требуют правок vendor.

### 3.3. Обновление, устаревание, конфликты (R-DOC-12/13)

* **Статус формулы**: `act_key` (вычисленный) ≠ `[state].act_key` → причины:
  `InputsChanged` (значения/обозначения), `FragmentsChanged` (act_key фрагмента), `SourceChanged`
  (правка LaTeX — семантика `ScriptChanged`), `ParamsChanged` (display/numbering), `EnvChanged`
  (версия рендерера), `CacheMissing` (нет блобов), `NeverComputed`.
* **Статус вставки**: `insert.hash ≠ formula.act_key` → «формула устарела»; кэш-текст в теле ≠
  `cached` при совпадающем act_key → «ручная правка» (`BodyModified`); target не резолвится →
  `MissingTarget`; смена `render_mode` → предложение переоформить.
* **Обновление документа** расширяет `update_document_transactional`
  ([`rde-doc/src/lib.rs:2618-2661`](../../crates/rde-doc/src/lib.rs#L2618-L2661)):
  план → пересчитать устаревшие формулы (пересборка кэшей, §2.4) → заменить содержимое sdt по
  `insert.id`/`para_id` → обновить `hash`/`cached`/`number` в `rde:doc` → перенумерация (auto) →
  бэкап/diff-предпросмотр → **одна** store-транзакция с корнями `formula/*` (для пересчитанных) и
  `document/<doc-id>` (атомарный откат, §7.3 п.7).
* **Конфликт с ручной правкой (R-DOC-13)**: перезапись sdt-содержимого запрещена, если пользователь
  правил формулу в теле вручную (сравнение содержимого sdt с последним записанным — по хешу
  фрагмента `rde:doc`); диалог: «принять значение / сохранить ручное (создать объект-формулу из
  ручной правки) / отложить». Ручная правка **не** теряется молча.
* **«Где вставлено»** (R-DOC-19): скан вставок всех документов по target-префиксу
  `rde://document/<doc>/formula/<fid>`; в UI — список документов/блоков + переход; при удалении
  формулы — предупреждение со списком вставок (или каскадное удаление вставок с подтверждением).

## 4. Граф, act_key, каскад, откат (P2/P3)

### 4.1. `act_key` формулы

Используем существующие примитивы `rde-hash` (без новой формулы домена, только новый вызов):

```
src_hash    = H("rde:formula-src:1" | canonical_json({latex, display, numbering.mode, numbering.number?}))
in_hash     = rde_hash::in_hash([
                группа "inputs"    (mode=hashed):  members[(alias, digest, source_uri)…]
                группа "fragments" (mode=hashed):  members[(alias, act_key(fragment), uri)…]
              ])
params_hash = H("rde:params:1" | canonical_json({title}))          # метаданные, влияющие на объект
env_hash    = H("rde:env:1" | "formula" | renderer_id+ver | "sha256" | vars{})
act_key     = rde_hash::act_key("formula", "rde/formula@1", in_hash, Some(src_hash), params_hash, env_hash)
```

* `renderer_id+ver` — версия WordCraft (и poppler для SVG) из сборки; апгрейд → `EnvChanged` →
  перекомпиляция кэшей (осознанно: меняется рендер).
* `script_hash`-слот переиспользуем под `src_hash` (нет исполняемого скрипта; `Some` отличает от
  «нет источника»), `kind="formula"` — домен в `act_key`.
* Группы сортируются `in_hash`/`group_hash` (порядок не важен), значения — JCS; act_key стабилен
  (C8: одинаковые входы → одинаковый ключ; изменение digest входа → другой ключ).
* `ref`-входы исключены из `in_hash` (§7.3 п.1).

### 4.2. Граф и каскад

* Узлы: артефакты (есть), формулы (новые), документы (стоки). Рёбра hashed:
  `constants/artifact → formula` (входы), `formula → formula` (фрагменты; в т.ч. меж-документные),
  `formula → document` (вставки; не хеш-ребро, а транзакция обновления документа).
* Формула **не может** быть входом артефакта (у `InputSpec` нет варианта formula) → циклов
  «артефакт ↔ формула» не бывает; циклы возможны только по фрагментам — детект DFS-раскраской при
  загрузке проекта и сохранении `formula.toml` (§7.3 п.3; существующий `find_cycle`,
  [`project.rs:256-313`](../../crates/rde-core/src/project.rs#L256-L313), расширяется на формулы).
* Топопорядок: формулы (зависимости раньше) → документы; `Project::dag_edges` сохраняет
  артефактный контракт, новые `Project::formula_edges`/`graph_edges` — надстройка (P2).
* Каскад: обновление артефакта/константы → статус формулы `Stale` → вставки документа «устарели»
  → «Обновить документ» пересчитывает формулы и вставки (R-DOC-12). Обновление формулы само по
  себе **не** переписывает документы молча: только пометка + явное обновление/авто-режим
  (`document_auto_update` уже есть в `rde.toml`).
* Откат: формульные кэши — store-транзакции (`formula-update`), документ — `document-update`;
  атомарное «обновить формулы+документ» = одна tx с корнями `formula/*` + `document/<id>`.
  `rde-dag::rollback` сейчас обрабатывает только `artifact/*` (комментарий в коде, строка 1436) —
  P3 расширяет: для не-`artifact/*` корней (документ, формула) вызывается rde-doc-восстановление из
  store (уже есть `restore_document_from_store`), для формул — восстановление `[state]`/кэшей.
* GC: кэши формул защищены корнями/окном отката/pins — новых механизмов не нужно.

## 5. Редактор: нативный WordCraft в панели RDE (P4)

### 5.1. Интеграция

* Точка: `RdeApp` → `EmbeddedEditor.app: WordApp` ([`rde-ui/src/lib.rs:383-387`](../../crates/rde-ui/src/lib.rs#L383-L387)),
  режим `DocMode::DocView` (там же `doc_view_ui`). Лента RDE (вкладка «Документ») получает группу
  **«Формулы»**: «Вставить формулу», «Изменить формулу», «Обновить формулы», «Нумерация»,
  «Показать служебные» (дерево).
* Панель формулы — нативная egui-панель под/над canvas DocView:
  `wordcraft_ui_egui::equation_tab::show(&mut ed.app, ui)` (спайк A: рисуется в egui-панели без
  правок vendor; а также `insert_button`/`builtin_menu` для кнопки ленты). Шрифты WordCraft
  (`medium`/`semibold`) обязательны — вызывать `wordcraft_ui_egui::theme::install_fonts(ctx)` до
  первого кадра панели (иначе паника; найдено на спайке A).
* LaTeX-поле: `egui::TextEdit` в панели RDE + кнопка «В источник» (применение); состояние LaTeX
  хранится в объекте (`formula.toml`), а не только в `Session.math_latex`; синхронизация:
  `equation.set {"latex": …}` (вставить объект в редактор), `equation.get` → `latex` (забрать
  правку), `equation.inputFormat {"format":"latex"}` — режим ввода.
* Предпросмотр: `previews::math_texture(&mut ed.app, ctx, key, &nodes, display, pt, size)` —
  тот же рендер, что у вкладки WordCraft; `nodes = wordcraft_engine::doc::math_latex::parse_latex(latex)`.
* Правка существующей: найти абзац по `para_id` (RDE хранит карту блоков/вставок), поставить
  каретку (`ed.app.session.sel` — публичное поле; команды «каретка к формуле» нет, см. §5.2),
  `equation.edit`, панель, по Apply — `formula.toml` + пересборка кэша + перезапись вставки.
* Нумерация: `formula.numbering` — объект-источник; отображение — таблица 1×2 (канон §9.4,
  реализована в фазе 1); auto-номера рассчитываются по порядку вставок при обновлении документа,
  manual — фиксированы (override с предупреждением, R-DOC-15); «сквозная/по разделам» — P4/P5
  (отдельно от объекта, в шаблоне документа).
* Webview/wry не используются нигде (решение владельца; NFR-LIC-02 — wry MIT, но запрет владельца
  на webview/JS-редакторы соблюдается).

### 5.2. Чего не хватает в WordCraft-API (зафиксировано спайком A; обходы без vendor-правок)

1. **Каретка к формуле объекта** — нет команды; обход: `session.sel` напрямую (RDE уже владеет
   `WordApp`) или `insert.equation` в текущую каретку.
2. **OMML как данные** — нет; обход: компиляция мини-документа (§2.4) / пост-обработка пакета.
3. **Экспорт формулы в SVG/PNG** — нет; обход: PDF → `pdftocairo` (§6) или vendor-фича (P5,
   upstream-кандидат).
4. **Номер формулы как поле Word/`SEQ`** — нет (writer пишет `#` в `m:t`); обход — таблица 1×2.
5. **Привязка объекта к формуле в модели** — нет поля/якоря; обход — sdt-тег/`paraId` на уровне
   пакета (RDE и так пост-обрабатывает пакет).

## 6. Вектор: SVG-кэш и экспорт (P5; частично P2)

### 6.1. Где SVG

* **Источник истины формулы — LaTeX/OMML** (R-DOC-22 п.1): в теле `.doc.rde` формула в режиме
  `omml` остаётся нативной и редактируемой; SVG — **кэш** (`svg_hash` в объекте, blob CAS) и
  режим вставки/экспорта.
* **PDF из WordCraft уже векторный** (спайк B1: `pdfimages` пуст, шрифт
  `DejaVuMathTeXGyre` embedded subset) — «формулы как картинки» для PDF не обязательны.
* **docx-режим «формулы как SVG»** (R-DOC-22 п.2 «отрендеренное изображение для совместимости»):
  вставка `w:drawing` с `asvg:svgBlip` + PNG-fallback (§3.2, точный XML — в отчёте спайка).
  LO 26.2 предпочитает SVG (вектор, `pdfimages` 0 строк; контроль PNG-only — 2 строки растра);
  Word 2016+ — по MS-ODRAWXML; **Word на стенде нет** → статус «по спецификации, фактически не
  проверено»; WordCraft читает PNG-fallback (на экране редактора — растр, это приемлемо).
* **Переприменение после сохранения**: WordCraft-writer теряет `svgBlip`/svg-медиа при
  пересохранении (спайк B6: 0 вхождений, svg-части нет). Поэтому RDE после каждого сохранения
  движком (уже: `write_package` в `save_engine_document`) **переприменяет** SVG-вставки из реестра
  `rde:doc`/кэшей (`render_mode="svg"`). Альтернатива — фикс writer в форке (P5, upstream-кандидат,
  ADR-0001 §4, feature-gate) — не требуется для работы.
* **PDF-гейт «нет растровых формул»** (`rde-docx`): для выходного PDF (Word или LO) —
  `pdfimages -list` не должен содержать изображений в областях формул (сверка bbox вставок или
  эвристика «число растров = число figure-вставок»); `pdffonts` — math-шрифт или пути.
  Для WordCraft-PDF гейт тривиален (0 растров, B1); для LO-пути — проверено на svgBlip (B5).
* Ограничения рецепта: кроп SVG через `pdftotext -bbox` работает, пока формула имеет текстовый
  слой в PDF (сейчас да: глифы + embedded font); если рендер станет «только пути» — bbox из
  layout-модели WordCraft/ink-bbox. Пайплайн зависит от poppler CLI (§15-2; при возврате к pdfium
  в v0.2 шаг перепроверить). Word-совместимость SVG-расширения — по спецификации, не проверена.

## 7. Миграция и совместимость (P3/P5)

| Что | Решение |
|---|---|
| `rde:doc` schema `1 → 2` | Новые поля `RdeInsert` (`kind="formula"`, `render_mode`, …) с `serde(default)`; старые пакеты читаются (дефолты = текущее поведение), новые атрибуты старый парсер игнорирует; при записи — `schema_version=2`. Миграция — при первом сохранении. |
| Формулы в старых документах | **Ленивое «принять как объект формулы»**: при открытии документа RDE считает OMML вне sdt `rde:formula:*` («формул вне реестра: N») и предлагает действие «Создать объект формулы из формулы документа» (LaTeX извлекается `to_latex`, объект создаётся, вставка регистрируется). Авто-миграции молча нет (аналог R-DOC-13). Демо (σ в разделе 2) мигрируется этим действием в P3 + тест. |
| Старый RDE читает новый проект | `formulas/` внутри документа — лишний каталог, загрузчик игнорирует (проверено C7: `issues=0`); `ConstantValue` с `source` — JSON Schema не запрещает доп. поля, serde игнорирует (C3); `value` остаётся обязательным → старый код валиден (показывает кэш/литерал). |
| `act_key`-совместимость | Литеральные константы хешируются как раньше (новые поля `skip_serializing_if` пусты) → старые артефакты не станут stale; константы с `source` — новый хеш, зависимые артефакты один раз покажут «изменились входы» и будут пересчитаны (не молчаливое изменение результата). Фиксируется golden-тестом. |
| Формулы и git | `formula.toml` — текст/diff; кэши не коммитятся; `[state]` — кэш (как `out_hash`). Конфликтные сценарии git — как у любых манифестов (§7.3 п.10). |
| Удаление/перенос | document-scope: удаление — корзина `.rde/trash/` (C10), перенос проекта — вместе; переиспользование между документами — только URI-фрагмент (зависимость без владения) или копия объекта. |

| Альтернатива | Почему отклонена |
|---|---|
| **Формулы на уровне проекта** (общие для всех документов) | Решение владельца: document-scope. Плюс: переиспользование и «одна формула — много вставок»; минус: владение/каскад/перенос документов неоднозначны, модель служебных объектов документа (R-DOC-19/20) нарушается. Переиспользование между документами сохранено через URI-фрагмент/копию (последствия: формула-фрагмент создаёт меж-документную зависимость; удаление документа-владельца ломает фрагмент — валидация/статус `MissingTarget`, вставки предупреждаются). |
| **Новый top-level тип «Формула»** | R-TREE-01 (базовый набор типов фиксирован) + R-DOC-20 (служебные объекты без нового типа). Формула — служебный объект-ребёнок документа. |
| **Отдельный тип «Величина»** | Решение владельца + R-ART-09: константы уже имеют типизацию/формат/входы в DAG; расширение дешевле и сохраняет act_key-механику. |
| **Формула как артефакт (compute-скрипт)** | Нет скрипта/окружения; компиляция формулы — рендер, а не запуск; иначе засоряются ledger/run/provenance-семантикой. Формула — вычисляемый узел без run. |
| **SVG генерировать своим рендерером OMML** | Дублирование WordCraft-математики; альтернатива через WordCraft PDF→`pdftocairo` проверена (B). Свой рендерер — потенциально без poppler, но это отдельный большой проект (P5+). |
| **Хранить изображение формулы как единственный формат** | Против R-DOC-22 п.1 (OMML редактируемый — основной). SVG — кэш/режим совместимости. |
| **Хранить кэши в git рядом с формулой** | Бинарные кэши в git (R-VCS-02): identity выходов — хеши в манифесте/ledger, блобы в CAS; git-дифф чистый. |

### 10.2. Риски и меры

| Риск | Мера |
|---|---|
| WordCraft-writer теряет `svgBlip`/svg-медиа при пересохранении (B6) | RDE переприменяет SVG-вставки после каждого сохранения движком; P5-кандидат — фикс в форке (feature-gated), не блокирует P1–P4 |
| Word на стенде отсутствует — Word-совместимость SVG только по MS-ODRAWXML | PNG-fallback даёт корректную видимость в любом Word/WordCraft; статус «не проверено в Word» в отчётах/CHANGELOG; проверка — на машине с Word (внешняя) |
| `act_key`-совместимость при расширении констант | Литералы хешируются как раньше (golden-тест); константы с `source` — явное одноразовое устаревание зависимых артефактов, не молчаливое изменение |
| Апгрейд WordCraft/poppler инвалидирует кэши формул | `env_hash` включает версию рендерера → причина `EnvChanged`, предсказуемая перекомпиляция |
| Миграция демо/старых документов | ленивое «принять как объект», не авто; тесты на `.doc.rde` schema 1→2 и обратную совместимость |
| Кросс-документные фрагменты: удаление/переименование владельца ломает зависимость | валидация при загрузке + статус `MissingTarget` у фрагмента/вставки + предупреждение при удалении («где вставлено») |
| Ручная правка формулы в теле vs обновление (R-DOC-13) | сравнение содержимого sdt с записанным; диалог «принять/сохранить/отложить»; ручная правка никогда не перезаписывается молча |
| Производительность компиляции формул (не измерялась) | P2: бюджет и замер (compile OMML/SVG на формулу, кэш по act_key); кэш в CAS исключает повторную компиляцию |
| `pdftocairo -svg` + bbox по текстовому слою | рецепт проверен (B2b); fallback — bbox из layout-модели/ink-bbox; зависимость poppler — уже принятое отклонение §15-2 (v0.2 — pdfium) |
| Формула в `rde:doc` и внешние правки Word | OMML в теле после правки Word может измениться → `list/formula.get` по якорю + OMML-гейт `rde-docx` (структура) → статус «ручная правка», предложение «принять как объект» |

## 12. Открытые вопросы владельцу (требуют ответа до P1)

1. **Подтвердить document-scope формул**: `objects/documents/<doc-id>/formulas/<fid>/`, владелец —
   документ, удаление/перенос — вместе с документом; переиспользование между документами — только
   URI-фрагмент (зависимость без владения) или копия. Последствия: перенос формулы в другой
   документ в v1 не поддерживается; удаление документа делает меж-документные фрагменты
   неразрешёнными (статус + предупреждение).
2. **Подтвердить формат SVG-вставки**: `asvg:svgBlip` + PNG-fallback (MS-ODRAWXML; LO 26.2 —
   проверено векторно, Word 2016+ — по спецификации, Word на стенде нет) и политику
   «RDE переприменяет SVG после сохранения движком» (WordCraft-writer теряет расширение).
3. **Место формулы в дереве**: служебный объект-ребёнок документа (скрыт, «показать служебные»,
   R-TREE-01/02) — или отдельная группа «Формулы» с фильтром.
4. **`value` при `source`**: оставить `value` обязательным кэшем последнего разрешённого значения
   (совместимость, рекомендуется) или разрешить value-less записи с повышением схемы
   `rde/artifact@1 → @2` (миграция + возможная несовместимость со старым RDE).
5. **Миграция inline-формулы демо** (σ в разделе 2): ленивое действие «принять как объект формулы»
   по команде пользователя (рекомендуется) или авто-миграция при открытии документа.
