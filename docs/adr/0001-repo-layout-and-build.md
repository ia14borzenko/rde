# ADR-0001: расположение репозитория, сборка и политика изменений WordCraft

| Поле | Значение |
|---|---|
| Дата | 2026-10-24 |
| Статус | принято |
| Контекст | Начало реализации RDE; решения владельца по опциям плана `.agent/plan-v01.md` §I |

## Решения

### 1. Продуктовый репозиторий — `rde-dev/rde/` (OP-02 = б)
- `rde-dev/` остаётся рабочим каталогом: `refs/` (библиотека референсов), `.agent/` (ТЗ и планы),
  `.build/` (артефакты сборки) — **вне** продуктового git-репозитория.
- Продукт: `/home/admin-pc/proj/rde-dev/rde/` — отдельный git-репозиторий (ветка `main`).
- `refs/` и `.build/` дополнительно перечислены в `.gitignore` продуктового репозитория.

### 2. Вендоринг зависимостей — сеть + кэш сейчас, `cargo vendor` перед релизом (OP-03 = а)
- WordCraft — git-субмодуль `vendor/wordcraft`, пин — тег **v0.10.0** (commit `9130181a`).
- craft-libs/krilla: пин через `[patch.crates-io]` в корне RDE (патчи воркспейса зависимости не
  применяются при сборке path-зависимости), сейчас тянется с GitHub по ревизии `c3487320…`.
- Перед первым релизом: `cargo vendor` + офлайн-режим в CI. Причина: не усложнять старт, но
  обеспечить воспроизводимость к релизу.

### 3. CI и платформы — Linux сейчас, но с обязательным слоем совместимости (OP-04 = ответ владельца)
- На этом этапе CI/сборка — Linux. Windows/macOS и Word-гейты — позже (нужен раннер с Office).
- **Обязательное требование:** весь платформо-зависимый код изолируется за абстракциями
  (`rde-platform`/traits, `cfg(target_os)` только в адаптерах, никаких путей ОС в доменной логике).
  Причина: будущий слой совместимости для других платформ не должен требовать переписывания домена.
  Практические следствия: пути/локи/процессы/сигналы/ассоциации файлов — только через адаптеры;
  тесты домена — платформо-независимые.

### 4. Изменения WordCraft — только через форк-ветку субмодуля (OP-05 = ветка в форке)
- Субмодуль `vendor/wordcraft` указывает на **наш форк**; изменения живут в ветке `rde/main`
  (до создания удалённого форка — локальная ветка в субмодуле с тем же именем).
- Каждое изменение WordCraft:
  1. отдельный коммит с префиксом `RDE: <компонент>: <что>` и обоснованием;
  2. запись в [`docs/wordcraft-fork.md`](../wordcraft-fork.md): дата, компонент, коммит, зачем,
     кандидат ли в upstream, как проверено;
  3. в RDE-репозитории — коммит, поднимающий пин субмодуля, со ссылкой на запись;
  4. по возможности — feature-gate, чтобы RDE-код можно было собрать и на чистом upstream.
- **Текущая итерация исходники WordCraft не меняет** (используются только публичные API),
  поэтому история изменений пока пуста.

### 5. Объём первой итерации — «общий вид концепции» (OP-12 = а)
- UI-каркас (дерево/вкладки/панели/статус-бар), реальный предпросмотр `.docx` через WordCraft,
  mock-данные DAG/агента/журнала.
- Итерация 1.1 (2026-10-24): в область документа **встроен полный `WordApp`** WordCraft через его
  публичный `WordApp::ui` — без изменения исходников (форк-ветка пока не нужна). Это промежуточный
  шаг, чтобы получить полноценный редактор; лёгкий `DocView`-виджет (без ribbon/titlebar WordCraft,
  нативный вид внутри RDE) — следующий спайк S5.
- Скриншоты — **виртуально, без видимых окон**: headless-рендер через `egui_kittest` + wgpu
  (`cargo run -p rde-ui --example screenshot`). На рабочий стол пользователя окна не выводятся.

## Последствия
- Быстрый старт без вендоринга и без изменения WordCraft; главный риск (сборка RDE-воркспейса
  с WordCraft-path-зависимостями) проверяется сразу первой сборкой.
- Форк-ветка и журнал изменений создают прослеживаемую историю развития Решения по компонентам.
- Платформенная абстракция закладывается с первого дня, хотя CI пока Linux-only.
