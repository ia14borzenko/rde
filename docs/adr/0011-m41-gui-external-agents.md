# ADR-0011: M4.1 — внешние агенты из GUI (встроенный MCP HTTP-сервер, настройка «Разрешить»)

| Поле | Значение |
|---|---|
| Дата | 2026-10-27 |
| Статус | принято |
| Контекст | v0.3, веха **M4.1** «человеческий UX внешних агентов»: ТЗ [`§5.10`](../tz-03.md) R-MCP-02 (настройка «Разрешить внешним агентам», loopback + bearer, выключено по умолчанию), R-MCP-05 (безопасность/аудит), [`§5.9`](../tz-03.md) (агент), [`§10.3`](../tz-03.md) п.6; [`ADR-0009`](0009-m3-streamable-http-transport.md) (M3: HTTP-транспорт CLI), [`ADR-0006`](0006-mcp-independent-layer.md) (слои), [`ADR-0002`](0002-component-boundaries.md) (инвариант 8) |
| Внешние опоры | `rde-mcp`: новый API `start_http_background` (`HttpServerHandle`/`HttpServerInfo`), `HttpOptions.announce/handle_ctrl_c`; `rde-host`: `HeadlessHost`/`HostHooks::jsonl`; `rde-core::AppSettings` — аддитивное поле `allow_external_mcp`; GUI — egui/eframe (без новых внешних зависимостей) |

## Контекст

M3 ([ADR-0009](0009-m3-streamable-http-transport.md)) дал transport streamable HTTP, включаемый **флагом
CLI** (`rde mcp serve --transport http`). R-MCP-02 требует **настройку «Разрешить внешним агентам»** в
приложении: пользователь включает доступ из UI, видит адрес/токен и копирует их во внешний клиент
(Claude Code и др.). Ограничения:

- fail-closed по умолчанию: без явного разрешения пользователя **никакого порта** не открывается;
- доступ — только loopback + обязательный bearer-токен; токен не должен утекать (не в логи, не в URL,
  не в файлы проекта);
- пока нет GUI-диалога approvals (реализован в **M4.2**), внешний агент должен быть **read-only** —
  мутации запрещены политикой (`approvals=deny`), иначе включение доступа станет небезопасным;
- сервер должен жить в фоне GUI, останавливаться при выключении настройки/смене проекта/выходе;
- минимальный дифф и сохранение слоёв (доменная логика — в библиотеках, UI — оркестрация).

## Решение

### 1. `rde-mcp`: управляемый фоновый сервер (`start_http_background`)

В [`http.rs`](../crates/rde-mcp/src/http.rs) добавлен API для встраивания (в дополнение к CLI-пути):

| API | Назначение |
|---|---|
| `start_http_background(host, hooks, policy, options) -> Result<HttpServerHandle, ServeError>` | поднимает сервер в фоновом потоке; возвращает хэндл сразу после bind; ошибки конфигурации/запуска — синхронно (через 15 с таймаут) |
| `HttpServerHandle { info(), stop() }` + `Drop` | адрес/токен (`HttpServerInfo`) для UI; `stop()`/`Drop` сигналят остановку и **дожидаются** завершения потока (порт закрывается, `shutdown_jobs` вызывается) |
| `HttpServerInfo { addr, token, generated }` + `url()/health_url()` | данные для панели «Агент» (URL `/mcp`, `/health`, bearer-токен) |
| `HttpOptions { bind, token, announce, handle_ctrl_c }` | `announce=false` — не печатать адрес/токен в stderr (их показывает GUI); `handle_ctrl_c=false` — Ctrl+C остаётся за приложением-хозяином |

Внутри `serve_http`/`start_http_background` общий цикл `run_http`: валидация bind/токена → `McpServer` →
`StreamableHttpService`+axum → bind → **ready** (адрес/токен отдаются вызывающему) → `serve` до
остановки (флаг `AtomicBool`/Ctrl+C) → отмена SSE-сессий + `shutdown_jobs`. Ошибки до `ready`
передаются вызывающему строкой (нет висящих потоков). Порт по умолчанию — `127.0.0.1:0` (эфемерный);
bind не-loopback отклоняется (R-MCP-02).

### 2. `rde-core::AppSettings`: аддитивное поле `allow_external_mcp`

`#[serde(default)] pub allow_external_mcp: bool` (default `false`): старые `settings.toml` читаются без
миграции, «внешние агенты» по умолчанию запрещены (fail-closed). `normalize()` поле не трогает.

### 3. `rde-ui`: менеджер сервера + настройка + панель «Агент»

- Новая зависимость GUI-ветки: `rde-ui → rde-host → rde-mcp` (GUI управляет **headless**-сервером; доменная
  логика не дублируется — инвариант 8 ADR-0002 соблюдён; обратных зависимостей нет: `rde-mcp` не знает
  про UI, `rde-host` — без egui).
- [`agent_server.rs`](../crates/rde-ui/src/agent_server.rs): `ExternalAgentServer` (start/stop/apply/
  on_project_switched, статус `Disabled|NotRunning|Running(HttpServerInfo)`, `last_error`) и
  `Drop`-остановка. Политика — `McpPolicy::read_only()` (approvals=deny), аудит — `HostHooks::jsonl`,
  `HttpOptions { bind: 127.0.0.1:0, token: None, announce: false, handle_ctrl_c: false }`.
- Настройки приложения: чекбокс **«Разрешить доступ внешним агентам (MCP, streamable HTTP)»** + пояснение
  «только loopback + bearer-токен, только чтение»; «Сохранить» применяет настройку — поднимает/останавливает
  сервер (ошибка запуска → журнал + настройка сбрасывается в выключено, fail-closed).
- Авто-старт: при старте RDE, если настройка включена, сервер поднимается лениво на первом кадре
  (**кроме unit-тестов**: в тестах авто-старт отключён, явное включение тестируется отдельно).
- Панель «Агент»: статус (`• MCP HTTP`/`остановлен`/`не подключён`), URL, токен (скрыт по умолчанию,
  «Показать/Скрыть токен»), кнопки «Копировать адрес»/«Копировать токен»/«Остановить доступ»/
  «Запустить доступ», ошибка запуска красным; ниже — секция «Встроенный агент (ACP)» с честным
  «M4.3». Строка статуса внизу показывает `Агент: MCP HTTP :порт` / `MCP: on :порт` (или off).
- Смена проекта (`open_project`) — старый сервер останавливается, при включённой настройке поднимается
  для нового корня; выход из приложения — `Drop for RdeApp` останавливает сервер.

### 4. Безопасность (fail-closed, R-MCP-02/R-MCP-05)

- Никакого порта без явного включения настройки (default `false`); только loopback; bearer-токен
  генерируется CSPRNG (32 байта) при старте, **не сохраняется** (ротация = перезапуск сервера),
  показывается только в UI (не в stderr при `announce=false`, не в аудите, не в URL);
- политика — read-only: мутации/запуск скриптов через внешний HTTP отклоняются (`RDE_APPROVAL_DENIED`);
  GUI-approvals с diff — **M4.2**;
- аудит: tool-call'ы и 401 — в `.rde/agent/audit.log` (JSONL, M3-механика);
- при ошибке запуска настройка сбрасывается в «выключено»; при выключении/смене проекта/выходе
  сервер останавливается и порт закрывается.

## Точки выбора (закрыты)

| # | Решение | Почему |
|---|---|---|
| O1 | фоновый сервер в GUI-процессе (не отдельный процесс) | простое владение жизненным циклом/токеном, не нужен IPC; `start_http_background` изолирует поток |
| O2 | read-only внешний доступ до M4.2 (реализовано в M4.2, ADR-0012) | без интерактивного approval нельзя безопасно разрешать мутации; R-MCP-05 fail-closed |
| O3 | токен только в UI, без сохранения на диск | GUI уже имеет защищённый канал к пользователю; файл-секрет требует ротации/защиты (CLI-путь — `--token-file`) |
| O4 | эфемерный порт `127.0.0.1:0` | нет конфликтов портов, не нужен конфиг; фактический адрес виден в панели |
| O5 | новая зависимость `rde-ui → rde-host/rde-mcp` | GUI владеет сервером; доменная логика остаётся в библиотеках (инвариант 8); `rde-mcp`/`rde-host` независимы от UI |
| O6 | авто-старт при настройке включена, но не в unit-тестах | UX: включил — работает после перезапуска; тесты не плодят фоновые порты |
| O7 | `announce/handle_ctrl_c` в `HttpOptions` | один код на CLI и GUI без ветвлений по процессу; CLI-поведение M3 не изменилось |

## Отклонённые альтернативы

1. **Разрешать мутации с `--approval=auto` из GUI.** Отклонено O2: без диалога approvals пользователь не
   контролирует действия агента; сначала M4.2 (интерактивный approval с diff/чекпоинтом).
2. **Отдельный процесс `rde mcp serve` под управлением GUI.** Отклонено O1: IPC/сигналы/логи/токен-передача
   усложняют; фоновый поток достаточен и проще тестируется.
3. **Фиксированный порт (например 8765) в GUI.** Отклонено O4: конфликты при нескольких экземплярах RDE;
   эфемерный порт + отображение адреса проще.
4. **Сохранять токен в настройках/`.rde`.** Отклонено O3: секрет на диске; ротация и утечки; CLI уже даёт
   `--token-file` для воспроизводимых сценариев.
5. **Показывать токен в stderr/логе как CLI.** Отклонено: в GUI stderr не виден, а логи могут собираться
   в диагностику; токен — только в панели с кнопкой копирования.
6. **Реализовать сразу и встроенного ACP-агента.** Отклонено по объёму: M4.1 — только внешний доступ (R-MCP-02);
   панель чата/ACP — M4.3.

## Последствия

- **M4.2 — реализовано** ([ADR-0012](0012-m42-gui-interactive-approvals.md)): интерактивный
  `ApprovalHook` в GUI — диалог с превью «Было/Станет»/аргументами и решениями «разрешить один раз/
  в сессии/отклонить»; сервер с грантом `allow_project_write` (run/git — M4.2b); тот же
  `start_http_background`, меняются политика/хук.
- **M4.3**: ACP-агент/панель чата — использует встроенный сервер (stdio/loopback) и `EventSink` для прогресса.
- **M4.4**: URI-чипы §8.7.2 и diff-UI suggested edits.
- Архитектурная стрелка `rde-ui → rde-host → rde-mcp` зафиксирована в ADR-0002/ADR-0006-контексте: доменные
  крейты по-прежнему не знают про UI; `cargo tree -p rde-mcp` — без `rde-*`/GUI.
- Внешний доступ по умолчанию **выключен** в settings; при включении — только чтение и только loopback.
- Бюджет MCP-контекста не менялся: 29 инструментов / 38 103 Б / инструкции 8 886 Б.

```bash
export CARGO_TARGET_DIR=/home/admin-pc/proj/rde-dev/rde/target

./scripts/build.sh run -p rde-ui --example screenshot -- /tmp/rde-m41.png document  # панель «Агент»

cargo tree -p rde-host | grep -E "egui|eframe|rde-ui"                                                      # пусто
```

Ручная проверка: RDE → Настройки приложения → включить «Разрешить доступ внешним агентам» → «Сохранить»;
в панели «Агент» появляется URL и (по кнопке) токен; `curl http://127.0.0.1:<порт>/health` → 200 без
токена; внешний клиент с `Authorization: Bearer <токен>` видит 29 инструментов, мутации отклоняются
(`RDE_APPROVAL_DENIED`); выключение настройки/смена проекта/закрытие окна останавливает сервер.
