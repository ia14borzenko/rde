## Контекст

P5 (ADR-0021) сделала собственный egui-WYSIWYG-редактор формул (`rde-math-editor`) на модели
WordCraft. Владелец после проверки решил заменить его **настоящим открытым визуальным LaTeX-редактором
уровня MathType** и допустил webview. Решения владельца (2026-10-31, дословно по смыслу):

1. Webview — **разрешён**; недостающую функциональность можно брать из других решений как референс и
   адаптировать (реверс-инжиниринг, не копирование кода).
2. UX — **как в MathType**: пользователь работает с визуальными элементами, а не с кодом.
3. Редактор — **отдельное окно** (MathType так и работает); при webview допустимо встроить окно в RDE.
4. **Рендер SVG вызывается внутри RDE** — чем именно, без разницы.
5. **OMML-режим вставки сохраняется** (`render_mode = omml | svg`), Word-совместимость не теряем.
6. **Кросс-платформенность желательна** (Linux первично, Windows); лицензии — только легально
   используемые; если легально использовать нельзя — реализовать функциональность самим.
7. Критерии приёмки владелец определит сам; агент сам определяет и выполняет технические критерии.

Ограничение стенда (спайк §1): рантайм WebKitGTK есть, но **dev-заголовков нет** (`pkg-config
webkit2gtk-4.1` → not found) и `sudo` запрещён → встроенный `wry`-webview собрать нельзя. При этом
Chrome 155 установлен. Поэтому выбран эквивалентный путь «отдельное окно установленного браузера в
режиме приложения»: это webview-класс UX, не требующий сборки webview-стека, `sudo` и системных
пакетов; владелец отдельное окно явно разрешил.

## Решение 1 — Архитектура редактора: MathLive (MIT) в отдельном окне браузера + loopback-мост

Новый крейт [`crates/rde-formula-editor`](../../crates/rde-formula-editor) (не зависит от UI):

1. **Ассеты в бандле (офлайн).** MathLive **0.111.1** (MIT) + шрифты KaTeX (MIT) + наша страница
   редактора упакованы `include_bytes!` в бинарник — **1 143 422 B ≈ 1,09 МиБ**. Рантайм полностью
   офлайновый: ни CDN, ни сетевых загрузок, ни внешних файлов (кроме самого браузера). Обновление
   ассетов — вместе с версией (`MATHLIVE_VERSION`), инвентаризация и лицензии — тестами.
2. **Окно.** RDE находит браузер (`RDE_FORMULA_EDITOR_BROWSER` → `google-chrome`/`chromium`/`brave`/
   `microsoft-edge`/`vivaldi`/`opera` → Windows: `msedge.exe`/`chrome.exe` → macOS: Chrome/Edge/
   Chromium) и запускает его в режиме приложения: `--app=http://127.0.0.1:<порт>/?t=<токен>` +
   изолированный профиль (`$XDG_CACHE_HOME/rde/formula-editor-profile`) + `--window-size` +
   `--disable-background-networking --disable-component-update --disable-sync …`. Нет браузера —
   fallback «браузер по умолчанию» (`xdg-open`/`open`/`start`); нет и его — понятная ошибка в панели
   (LaTeX-поле остаётся рабочим). Графическая сессия определяется `display_available()` (на headless
   авто-открытие по клику отключается, окно открывается только явной кнопкой).
3. **Мост JS↔Rust.** Свой минимальный HTTP/1.0 на `std` (без async): слушает **только**
   `127.0.0.1:<случайный порт>`; страница получает состояние (`GET /api/state`: LaTeX/display/title/
   theme/zoom/project) и отправляет действия (`POST /api/apply {latex}`, `/api/cancel`, `/api/prefs
   {zoom}`). События — `std::sync::mpsc`, RDE опрашивает очередь в каждом кадре (неблокирующе).
   Безопасность: одноразовый токен 16 байт CSPRNG (64 hex), сравнение за постоянное время, проверка
   `Host` (anti-DNS-rebinding), лимиты тела/заголовков, таймауты, CSP страницы `default-src 'self'`,
   `nosniff`, `no-store`. Из страницы исполняется **только** этот ограниченный протокол: LaTeX —
   данные, никакого кода RDE/проекта.
4. **Жизненный цикл.** Окно живёт в [`FormulaEditorState`](../../crates/rde-ui/src/lib.rs)
   (`editor_window`); тема RDE транслируется в окно каждый кадр; зум 100–200 % сохраняется
   (`~/.config/rde/formula-editor.toml`); «Применить» → `EditorEvent::Applied{latex}` → окно
   закрывается (kill process group) → LaTeX применяется конвейером панели; «Отмена»/закрытие окна
   крестиком → без изменений; падение браузера — «Отмена» + сообщение, источник не портится.

**Отвергнутые альтернативы:**

| Альтернатива | Причина отказа |
|---|---|
| `wry`/`webkit2gtk` (встроенный webview) | нет dev-заголовков `webkit2gtk-4.1`/GTK, `sudo` запрещён; сборка невозможна (спайк §1) |
| Локальный sysroot из `.deb` | не воспроизводимая сборка, «системные пакеты не ставить» (ТЗ §6) |
| План B: MathType-класс на egui | допустим, но это отказ от готового MathLive-класса UX; P5 уже показал объём/предел своего WYSIWYG; выбран как fallback только при отсутствии webview-пути |
| MathJax/KaTeX как редактор | это рендереры, не редакторы; SVG-рендер документа уже есть в RDE (WordCraft+poppler, visual parity) |
| `latex-rust` / `mathtex-editor` | разобраны и отклонены в P5-спайке (нет модели редактирования / лицензия+`format.pkg`) |
| Внешние GPL-редакторы (KLatexFormula, TeXmacs…) | не в бандл (NFR-LIC); только референс UX |

## Решение 2 — LaTeX остаётся источником истины; панель — место записи

* `formula.toml.latex` — канонический источник; схема **не меняется** (новых полей нет).
* Окно открывается на текущем LaTeX (`dialog.latex`), возвращает LaTeX строкой; «Применить» в окне —
  **явное действие пользователя**: кандидат проходит `rde_doc::check_formula_latex` (запрет
  плейсхолдеров/Unicode-заменителей линейного формата из инцидента P5; предупреждение, если
  структура меняется) → существующий конвейер `apply_formula_edit`/`create_formula_action`
  (нормализация, `compile_formula` → OMML/SVG/PNG кэши, ledger, `body_hash`, Fresh/Stale).
* Никакого автосинка при закрытии/скрытии окна нет (правило ADR-0021 §Решение 2 сохраняется).
* Панель «Формула»: LaTeX-поле (источник/витрина), предпросмотр формулы из кэшей (PNG из CAS →
  ink-mask с тинтом темы), display/inline, нумерация, режим вставки, «Открыть редактор формул…»,
  «Применить»/«Вставить в документ»/«Обновить документ». Старый WYSIWYG-виджет P5 удалён из UI;
  крейт `rde-math-editor` **удалён из workspace и репозитория** (история — в git).

## Решение 3 — SVG-вставки: основной режим display-формул; метрики и baseline

* Вставки по-прежнему двух режимов (`render_mode = omml | svg`, ADR-0018/0019/0020 без изменений
  семантики: right-numbered табами, `number_source`, `suffix`, crossrefs, ledger). **Новый режим по
  умолчанию в панели — `svg`** (OMML остаётся опцией и не ломает существующие проекты с OMML).
* Порядок вставки: картинка в `--app`-окне — не единственное место рендера: **SVG для документа
  рендерит сам RDE** прежним конвейером (`compile_formula`: WordCraft mini-doc → PDF → `pdftocairo
  -svg` → кроп по ink-bbox, глифы путями, PNG-fallback через resvg; ADR спайка P0). Визуальный
  паритет с документом сохраняется (тот же STIX/WordCraft layout).
* **Метрики вёрстки** (P6): `rde_doc::formula_metrics(latex, display) -> FormulaMetrics { width_pt,
  ascent_pt, descent_pt }` — из `MathLayout` той же вёрстки WordCraft. Используются при вставке:
  * display-формула SVG + номер: `<w:drawing>` — inline-объект, Word/WordCraft ставят его **низ** на
    базовую линию абзаца, поэтому номер `(N)` поднимается `<w:position w:val="…half-points"/>` на
    `descent + отступ кропа` — базовая линия номера совпадает с формулой (LO-оракул: см. §«Baseline»).
  * inline-формула: по умолчанию **OMML** (нативная математика, точный baseline). SVG inline
    остаётся доступным выбором, но имеет ограничение OOXML: низ картинки = базовая линия, поэтому
    нижние индексы приподняты на `descent`; это зафиксировано в UI-подсказке и в §«Ограничения».
* Baseline-ограничение проверено спайком (§4): inline-картинку в WordprocessingML нельзя опустить
  под базовую линию ( `<w:position>` не сдвигает drawing в LO; WordCraft: «A picture sits on the
  baseline of its run»). Это осознанное решение: SVG — для display, OMML — для inline.
* Отступ кропа стал публичной константой `rde_doc::SVG_CROP_PAD_PT = 2.0` (одна точка правды для
  рендера и выравнивания номера). Кэш-схема/`FORMULA_RENDERER_VERSION` **не меняются**: байты
  OMML/SVG/PNG те же, метрики вычисляются из LaTeX при вставке (постоянная стоимость ~0,2–1 мс), это
  не меняет `act_key`/ledger и не инвалидирует существующие проекты.

## Решение 4 — Ассеты, лицензии, офлайн, поставка

* В репозиторий коммитятся только MIT-ассеты: MathLive 0.111.1 (MIT, Arno Gourdol) и 20 шрифтов
  `KaTeX_*.woff2` (MIT, Khan Academy; 20/20 побайтово идентичны `katex@0.19.1`). Тексты лицензий —
  `crates/rde-formula-editor/assets/licenses/`, атрибуция — `NOTICE`. Обновление — вместе с версией,
  инвентаризация проверяется тестом (`asset_inventory_is_bundled_and_licensed`).
* Бандлятся только page/JS/CSS/шрифты; звуки MathLive (`sounds/`) не бандлятся
  (`MathfieldElement.soundsDirectory = null`). Внешних сетевых загрузок в бандле нет (grep в тесте и
  спайке; XML-namespace строки — не сеть).
* Браузер **не бандлится**: RDE использует установленный пользователем Chrome/Chromium/Edge; их
  лицензии — на пользователе (как и ОС).
* Кросс-платформенность: Linux (X11/Wayland — путь запуска одинаков, на стенде нет графической
  сессии: проверено headless-эквивалентом), Windows — `msedge.exe` (входит в ОС) как первый
  кандидат; macOS — Chrome/Edge/Chromium/`open`. Ручная проверка Windows/Wayland — `unverified`
  (нет стендов), помечено в отчёте.

## Baseline: LO-оракул (измерения)

Синтетический `.docx` (11 pt текст, inline-PNG 20 pt), LO 26.2.6.3 → PDF → 300 dpi:

| Измерение | Значение |
|---|---|
| Базовая линия текста («Aa») | 76,32 pt (низ глифов) |
| Низ inline-картинки (20 pt, прозрачная полоса 1 pt снизу) | 75,60 pt «чернил», 76,60 pt низ картинки |
| Расхождение | **0,28 pt** (растеризация/антиалиасинг) → **низ картинки = базовая линия** |
| `<w:position w:val="-10"/>` на run картинки | картинка **не сдвинулась** (75,60–56,64 pt) → inline-drawing позицией не опустить |

Вывод: `w:position` применяется к **тексту** (номер `(N)` — текст), но не к `w:drawing`; поэтому
номер поднимаем, картинку — нет. Подтверждено рендером документа: `gui-p23-formula-svg-document.png`
(формула по центру, номер `(1)` справа на её базовой линии).

## Влияние и лицензии

* **ADR-0005 §5.1** («Webview/wry не используются нигде») — **изменён**: webview разрешён владельцем
  (2026-10-31), реализован как отдельное окно системного браузера; встроенный webview-стек не
  добавляется (сборка на стенде невозможна). Формулировка изменения — здесь и в ADR-0005.
* **ADR-0021** — помечен «superseded by ADR-0022» в части редактора (P5 WYSIWYG). Его решения о
  safety (`check_formula_latex`) и сохранении позиции документа остаются действующими.
* **ADR-0018/0019/0020** — без изменений семантики (STIX, right-numbered, нумерация, ledger/CAS,
  статусы, импорт MathType). SVG-вставки — существующий режим, дополнены метрики/номер.
* **Vendor/WordCraft** — правок нет; используются публичные API (`layout`, `parse_latex` — как и в
  P5 через `rde-doc`).
* **Лицензии**: +2 MIT-компонента (MathLive, шрифты KaTeX) в бандл, атрибуция в `NOTICE`; новых
  зависимостей в `Cargo.lock` нет.
* **Перф**: страница окна готова 0,93 с холодно / 0,77 с тепло (headless Chrome, этот стенд; включая
  инициализацию MathLive и загрузку состояния); apply POST ~1–3 мс; «Обновить документ» — прежний
  конвейер (+`formula_metrics` на каждую SVG display-формулу, ~0,2–1 мс release); SVG-рендер
  формулы — `compile_formula` (замер — `docs/fidelity/p23-perf.md`).

## Ограничения и риски (честно)

1. **Word-проверка** — на стенде Word нет; SVG/номер/baseline проверены LO-оракулом и WordCraft-
   рендером, Word — `unverified`.
2. **Windows/Wayland** — пути запуска браузера заложены, ручной проверки нет (`unverified`).
3. **Inline SVG** — baseline-ограничение OOXML (см. §Baseline): для inline по умолчанию OMML.
4. **Визуальный стиль окна** — KaTeX-типографика MathLive (MathType-класс), документ — STIX/WordCraft;
   официальной подмены math-шрифта MathLive нет (спайк §3).
5. **Зависимость от браузера** — нет Chrome/Edge/Chromium → fallback в браузер по умолчанию или
   ошибка с сохранением работоспособности панели; окно — внешний процесс (память/закрытие
   контролируются RDE).
6. **Кастомизация палитр под ГОСТ/матричный тулбар** — P2-бэклог; базовый MathType-класс UX уже есть.
