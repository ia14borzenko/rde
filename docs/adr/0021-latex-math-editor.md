# ADR-0021 — LaTeX-редактор формул: выбор движка и архитектура (P5)

- **Статус:** принято (2026-10-29, итерация `math-editor`, P5); **Phase 1 и Phase 2 (MVP) реализованы**
  в этой же итерации — итог в §«Итог реализации MVP»
- **Контекст:** недовольство владельца редактором P4 (ADR-0020): «клон Microsoft Equations», лаги,
  **порча формулы при навигации** (мусор `√`/`▒` из `equation.get` попал в `formula.toml`),
  «Обновить документ»/вставка сбрасывают документ на первую страницу; требование — **аналог
  MathType**, а не MS Equations, **LaTeX-формулы** как источник истины.
- **Связанные документы:** [спайк Research Gate](../spikes/latex-editor.md),
  [ADR-0005](0005-formulas-and-values-as-project-objects.md) (§5.1 webview-запрет, P4/P5),
  [ADR-0018](0018-formula-math-font-and-right-numbered.md) (STIX/Word-вёрстка),
  [ADR-0019](0019-import-numbered-formulas.md) (импорт MathType),
  [ADR-0020](0020-formula-editor-ui.md) (редактор P4 — заменяется),
  [ADR-0001](0001-repo-layout-and-build.md) §4 (правило форка WordCraft),
  [ADR-0002](0002-component-boundaries.md) (границы крейтов),
  [`docs/tz-03.md`](../tz-03.md) §4 (NFR-PERF-01), §0.4 (NFR-LIC-01/02), §16,
  [`docs/state.md`](../state.md), [`docs/wordcraft-fork.md`](../wordcraft-fork.md).
- **База:** HEAD `3e21164` (тег `formula-tab`), рабочее дерево чистое; на входе workspace
  **592 passed / 0 failed**. Спайки — [`docs/spikes/latex-editor.md`](../spikes/latex-editor.md).
- **Vendor:** `vendor/wordcraft` (пин `33213040`) — **правок не требуется**: всё делается через

## Контекст

P4 (ADR-0020) закрыл создание/правку `formula.toml` и вставку формул, но сам «профессиональный
редактор» — это нативная вкладка Equation WordCraft (`equation_tab`), визуально и поведенчески
повторяющая Microsoft Equations. Владелец её отверг: нужен **MathType-класс** (структурный
WYSIWYG-ввод, палитры, клавиатура, undo/redo, LaTeX как источник истины), без лагов и без порчи
данных. Дополнительно подтверждены два инцидента:

- **A. Порча формулы**: `sync_formula_from_native` копировал `equation.get.latex` в панель **без
  проверки**; при линейном состоянии/конвертациях `equation.get` возвращает не-LaTeX (Unicode `√`,
  placeholder-глифы `▒`), и «Применить» записывал это в `formula.toml`.
- **B. Сброс позиции**: после «Обновить документ»/вставки/rollback код делал
  `self.editor = None; self.doc = DocPreview::new(...)` → `ensure_editor` заново открывал документ
  с начала (потеря каретки/страницы; на 250-й странице — «мотать обратно»).

## Решение 1 — движок и архитектура: вариант (c), «WordCraft math engine + собственный UI»

По матрице Research Gate ([спайк §4](../spikes/latex-editor.md)):

| Вариант | Итог |
|---|---|
| `latex-rust` (рендер) | отклонён как **основа редактора**: только рендер, нет модели/каретки/слотов/hit-test; другой TeX-лейаут → нет visual parity с документом |
| `mathtex-editor` (готовый UX) | отклонён: лицензия движка (`mathtex-portable-engine-generated` — производная TeX/eTeX/XeTeX, non-standard «all rights reserved») несовместима с NFR-LIC-01/02; требует bootstrap `format.pkg` из TeX Live под конкретную сборку движка; нет импорта LaTeX |
| **WordCraft math + свой UI** | **принят**: модель/операции/вёрстка/растр — документные (тот же STIX-конвейер), новые зависимости не нужны, visual parity by construction |
| webview (MathLive) | не рассматривался к внедрению: запрет владельца (ADR-0005 §5.1); нативный путь даёт паритет — вопрос владельцу не требуется |
| внешние GPL (LyX/TeXmacs/…) | не в бандл, только референс UX |

Архитектура (эскиз; код — Phase 2):

1. **Модель** — `wordcraft_doc::math::{Arg, MNode}` + `math_edit::MathPos` (path/off) — та же модель,
   что у документа. Никакого второго AST.
2. **Источник истины** — `formula.toml.latex` (не меняется, ADR-0005). Импорт LaTeX в модель —
   вендорный `math_latex::parse_latex`; экспорт — **собственный roundtrip-safe сериализатор**
   (см. Решение 2).
3. **Вёрстка/рендер** — scratch-`Document` с одной формулой → `layout::layout` → `MathLayout`
   (`width/ascent/descent/slots`) → `render::render_area` (vello_cpu, STIX, ink-mask) →
   `egui::TextureHandle`; кэш по `(модель+display+pt+zoom+ppp+тема)`. Каретка/выделение/подсветка
   аргументов — egui-оверлей из `MathLayout::{slot, hit, arg_extent}`.
4. **Ввод** — клавиатура/мышь → `math_edit` (`insert_text`, `insert_nodes`, `delete_back/forward`,
   `move_left/right/vertical`, `next_placeholder`, `build_up`, `autocorrect`, `structure_actions`,
   `apply_structure`, `set_limits`); шаблоны — `math_gallery::templates()` (222), символы —
   `math_gallery::SYMBOL_SETS` (8), готовые формулы — `BUILT_INS` (14). Undo/redo — стек снапшотов
   `Arg` + `MathPos`.
5. **Интеграция** — панель вкладки ленты «Формула» (как P4): открытие по клику на формуле в тексте,
   «Применить» → `update_formula_source` → `compile_formula`/ledger, «Вставить в документ» /
   «Обновить документ» — существующий конвейер без изменений. Старый нативный `equation_tab`-окно
   **удаляется из UI** (код — изолируется/удаляется после MVP); второй `WordApp` в кадре не
   создаётся (редактор — один egui-виджет, ADR-0020 §3 больше не актуален).
6. **Крaт** — новый `crates/rde-math-editor` (модель/кодек/геометрия/рендер-кэш/виджет) + интеграция
   в `rde-ui`; `rde-ui/src/lib.rs` не разрастается. Зависимости — только workspace-крейты +
   `wordcraft-engine` (уже есть), `egui` (уже есть).

## Решение 2 — LaTeX-источник истины и безопасность записи

Спайк показал: вендорный `to_latex` **не полностью roundtrip-safe** (9/316 случаев: пустые строки
матриц, `\ `-пробелы, `array` colspec, `\binom`→`\genfrac`, который парсер не понимает).
Поэтому:

- **Свой сериализатор** `rde-math-editor::source::to_latex(&Arg)`: канонический, с явными группами
  `{}`, без Unicode-плейсхолдеров; критерий — `parse_latex(to_latex(model)) == model` и
  `to_latex ∘ parse` идемпотентен на корпусе (демо + 62 MathType-формулы + все шаблоны + P0-набор).
- **Правило «нет тихой записи»**: в `formula.toml` пишется только LaTeX, прошедший валидацию:
  (а) парсится в модель; (б) каноническая форма равна модели редактора; (в) не содержит
  placeholder/мусорных символов (`▒`, `█`, `⬚`, `■`); (г) редактирование — только явное действие
  «Применить». Автосинк при закрытии/скрытии — запрещён.
- **Safety-фикс A (Phase 1, до нового редактора):** `sync_formula_from_native` получает валидацию
  «новый LaTeX семантически эквивалентен текущему» (сравнение нормализованных AST; для невалидного —
  ошибка в панели, `dialog.latex`/`formula.toml` не трогаются). Кнопка «Забрать LaTeX из редактора»
  остаётся только как эксперимент с показом diff или скрывается вместе с проф. редактором; в UI
  «Проф. редактор…» временно **скрывается** (владелец ненавидит этот UX).
- **Регресс-тест A:** открыть нативную формулу → стрелки/конвертации → `equation.get` → sync:
  источник не изменился / валидация отказала. Фикстура испорченной формулы — в тесте (не в
  `formula.toml`).

## Решение 3 — сохранение позиции документа (Phase 1)

Причина сброса — пересоздание `WordApp`/`DocPreview` при любом обновлении пакета. Решение:

- **In-place reload редактора**: сохранить `session.sel` (+`page_hint`) → пересобрать `.docx` из
  пакета → `io::open_path_in` → заменить `session.doc`, `session.path`, `touch()`+`relayout()`,
  восстановить `session.sel`, `clamp_selection()`, `canvas.scroll_to_caret` (offset камеры остаётся в
  том же `CanvasState`). `editor`/`editor_error` не пересоздаются; undo-история сбрасывается
  (документ пересобирается — фиксируется как допустимое).
- **Все пути обновления** (вставка, «Обновить документ», «Обновить всё», rollback, миграция,
  оформление) используют единый хелпер `reload_document_view_preserving()` вместо
  `self.editor=None; self.doc=DocPreview::new(...)`; при смене/открытии проекта или документа —
  осознанный сброс (позиция чужого документа не переносится).
- **Предпросмотр страниц**: `preview_scroll_offset` переживает `DocPreview::new` (сохранённый offset
  восстанавливается один раз после появления страниц); колесо/ползунок не ломаются.
- **Тесты**: длинный документ (300 стр. из `rde-docx/tests/corpus/06-long-300.docx`), глубокая
  позиция (≈250-я страница) → «Обновить документ»/вставка → каретка/страница не первая; kittest —
  колесо/ползунок предпросмотра.

## Решение 4 — удаление старого редактора и документов

## Отвергнутые альтернативы (сводно)

1. **`latex-rust` + собственный редактор** — см. Решение 1: только рендер, нет геометрии/модели,
   другой лейаут; объём — редактор с нуля, visual parity недостижим.
2. **`mathtex-editor`-семейство** — лицензионный блокер (производная TeX, non-standard) и
   `format.pkg`/TeX Live bootstrap; нет импорта LaTeX.
3. **Webview (MathLive)** — архитектурный запрет владельца; нативный путь даёт паритет.
4. **Починка UX WordCraft `equation_tab`** — владелец отверг сам класс UX (клон MS Equations).
5. **Собственный TeX-layout «с нуля»** — несоизмеримый объём, дублирование документного движка.

## Риски

1. **Свой сериализатор**: неполное покрытие экзотики MathType-импорта → fallback «не записывать,
   показать ошибку»; корпусные roundtrip-тесты.
2. **Вендор-API**: при обновлении пина WordCraft публичные `MathLayout`/`render_area` могут
   измениться → фиксируем используемый срез тестами, обновление — по ADR-0001 §4.
3. **Перф**: растр на изменение модели; при регрессии — кэш/асинхронный пересчёт; замеры в отчёте.
4. **Visual parity**: редактор в панели рендерится тем же конвейером, что документ; разница — только
   масштаб панели (обоснованно).
5. **Объём MVP**: 3D-ввод/матричный тулбар/выравнивания — P1, честно фиксируются как отложенные,
   если не входят в итерацию.

### Уточнение по вводу (после первой проверки владельцем, 2026-10-30)

Клик по полотну и клавиатура в редакторе используют штатный egui-фокус с **focus-lock-фильтром**
(как `TextEdit`): стрелки/Tab/Esc принадлежат редактору и не переключают виджеты оболочки;
клик переводится в координаты картинки как `(pointer - origin) * ppp` с клампом к краям
(справа/снизу — конец формулы, слева/сверху — начало), каретка/выделение учитывают поля растра.
Регресс-тесты — `crates/rde-math-editor/tests/widget_input.rs` (5 kittest-тестов). Дополнительно
при открытой панели «Формула» скрытый живой canvas документа не создаётся (он авто-запрашивал
клавиатурный фокус и перехватывал стрелки/Tab): клавиатура принадлежит редактору формулы, после
«Закрыть» документ возвращается — тест `formula_editor_panel_owns_keyboard_focus` в `rde-ui`.

### Ограничения MVP (честно; P1 → следующая очередь)

1. **Пустые хвостовые строки матриц/`aligned` не представимы** в LaTeX-источнике нашим парсером:
   `normalize` отбрасывает их при записи (пустые ячейки внутри строк сохраняются; после заполнения
   строк всё представимо). Визуально: незаполненная «лишняя» строка матрицы при переоткрытии
   исчезнет. Расширение — свой парсер/вендор-патч (P1).
2. **Дроби без черты/наклонные** (шаблоны `frac.nobar/skewed/linear`) нормализуются в обычную
   `\frac` (парсер их не различает; `\binom` сохраняется). Цвет/фон/`m:phant` с частичным
   скрытием — не представимы, нормализуются.
3. **Подсветка выделения** — в пределах одного аргумента; через границы структур каретка двигается,
   но подсветка аргументов — P1 (MatrixType-подобное «выделить структуру» — `argument_extent` уже
   есть, UI — P1).
4. **MathML/OMML-копипаст** (P1): сейчас — только LaTeX-копипаст через поле источника; OMML-вставка
   в документ существует (существующий конвейер).
5. **Сложные имена функций** (`sin^{-1}`-шаблоны) разворачиваются в последовательность (визуально
   то же, `m:func` теряется) — P1.
6. **Клавиатурные шорткаты MathType** (вставка структур горячими клавишами) — базовый набор
   (стрелки/Tab/Esc/Backspace/Ctrl+Z/Y/A) есть, полная таблица — P1.
